# Zele Econometric Models

FastAPI service for serving econometric predictions for Pereira, Colombia. The
repository combines an API, a small SQLite-backed model catalog, authenticated
prediction endpoints, and offline notebooks used to prepare and train the OLS
models shipped as serialized artifacts.

## What This Repository Does

The application exposes three econometric models:

| Model key | Target | Purpose |
| --- | --- | --- |
| `econ_growth` | `delta_ln_PIB` | Estimates expected GDP growth from trade, remittances, net investment, and business activity. |
| `unemployment` | `delta_ln_TD` | Estimates expected change in unemployment from economic, trade, poverty, and competitiveness indicators. |
| `business_growth` | `delta_ln_EMP` | Estimates expected growth in active businesses from GDP, exports, and remittances. |

Predictions require an authenticated user. Missing input values are resolved
with this fallback order: request value, saved user value, seeded variable
default, then `0.0` if no variable metadata exists.

## Technology Stack

- Python 3.12+
- FastAPI and Uvicorn for the HTTP API
- SQLAlchemy with SQLite for persistence
- Pydantic and pydantic-settings for schemas and configuration
- python-jose and bcrypt for JWT cookie authentication and password hashing
- statsmodels, scikit-learn, pandas, seaborn, and matplotlib for modeling work
- Poetry 2.x for dependency and virtual environment management
- pytest and httpx for tests

## Data Directory

Runtime data lives in `data/`:

| File | Description |
| --- | --- |
| `data/zele-econometric-models.db` | SQLite database containing users, model catalog rows, variable metadata, model-variable relationships, and saved user input values. |

Training notebook data lives in `notebooks/data/`:

| File | Rows | Description |
| --- | ---: | --- |
| `model_data.csv` | 21 | Source dataset with annual macroeconomic, labor, trade, remittance, business, population, poverty, and competitiveness variables. |
| `model_data_transformed.csv` | 21 | Derived dataset with shortened variable names, logarithms, and log-change rates used by the models. |

Do not treat the SQLite database or model artifacts as source code. They are
runtime/model assets and should only be changed intentionally.

## Seed Data

In `development`, startup creates database tables and runs `seed_database` from
`src/seed.py`. Other environments skip this bootstrap path, so their database
and required artifacts must already exist.

Seeded models:

| Name | Display name | Target | Variables |
| --- | --- | --- | --- |
| `econ_growth` | Determinants of Pereira Economic Growth | `delta_ln_PIB` | `delta_ln_EXP`, `delta_ln_IMP`, `delta_ln_REM`, `delta_ln_INV`, `delta_ln_EMP` |
| `unemployment` | Determinants of Unemployment in Pereira A.M. | `delta_ln_TD` | `delta_ln_PIB`, `delta_ln_EXP`, `delta_ln_IMP`, `IPM`, `IDC` |
| `business_growth` | Determinants of Business Fabric Growth | `delta_ln_EMP` | `delta_ln_PIB`, `delta_ln_EXP`, `delta_ln_REM` |

Seeded variable dictionary:

| Variable | Meaning | Type | Default | Range | Step |
| --- | --- | --- | ---: | --- | ---: |
| `delta_ln_EXP` | Approximate export growth rate. | `log_change_rate` | `0.05` | `-0.50` to `0.50` | `0.01` |
| `delta_ln_IMP` | Approximate import growth rate. | `log_change_rate` | `0.03` | `-0.50` to `0.50` | `0.01` |
| `delta_ln_REM` | Approximate remittance growth rate. | `log_change_rate` | `0.02` | `-0.50` to `0.50` | `0.01` |
| `delta_ln_INV` | Approximate net investment growth rate. | `log_change_rate` | `0.01` | `-1.00` to `1.00` | `0.01` |
| `delta_ln_EMP` | Approximate active-business growth rate. | `log_change_rate` | `0.04` | `-0.30` to `0.30` | `0.01` |
| `delta_ln_PIB` | Approximate GDP growth rate. | `log_change_rate` | `0.07` | `-0.30` to `0.30` | `0.01` |
| `IPM` | Direct percentage of population in multidimensional poverty. | `percentage` | `15.0` | `0.0` to `60.0` | `0.5` |
| `IDC` | Normalized departmental competitiveness index. | `normalized_index` | `5.5` | `0.0` to `10.0` | `0.1` |

The seed is idempotent for catalog metadata: existing model and variable rows
are updated, and missing model-variable relationships are inserted.

## Model Artifacts

The API loads serialized statsmodels artifacts from `src/models/artifacts/v1/`
when `PredictionService` is instantiated. These files are required:

| Artifact | Model key |
| --- | --- |
| `econ_growth_model.pkl` | `econ_growth` |
| `td_model.pkl` | `unemployment` |
| `emp_model.pkl` | `business_growth` |

If an artifact is missing, the application fails during import/startup of the
prediction routers. Regenerate artifacts from `notebooks/02_base_model.ipynb`
and place them in `src/models/artifacts/v1/`.

## Training Notebooks

- `notebooks/01_eda.ipynb`: exploratory data analysis and correlation outputs.
- `notebooks/02_base_model.ipynb`: base model training and artifact generation.
- `notebooks/output/`: generated CSVs with correlation matrices and top correlations.

## Configuration

Copy `.env.example` to `.env` and adjust values for your environment.

| Variable | Default | Purpose |
| --- | --- | --- |
| `NODE_ENV` | `development` | Controls startup bootstrap and auth cookie security mode. |
| `SQLITE_DB_PATH` | `./data/zele-econometric-models.db` | SQLite database path. |
| `PORT` | `8000` | Uvicorn port. |
| `JWT_SECRET_KEY` | development default in code | Secret used to sign JWTs. Use a strong secret outside local development. |
| `JWT_ALGORITHM` | `HS256` | JWT signing algorithm. |
| `JWT_ACCESS_TOKEN_EXPIRE_MINUTES` | `60` | Auth cookie token lifetime. |
| `ALLOWED_ORIGINS` | local Vite origins | CORS origins allowed to send credentials. |

In production, auth cookies are set with `Secure` and `SameSite=None`. In other
environments they use `SameSite=Lax` and are not marked secure.

## Installation

```bash
poetry install
```

Poetry is configured to create the virtual environment inside the repository as
`.venv/`.

## Running The Server

Development:

```bash
NODE_ENV=development poetry run uvicorn src.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

Development startup validates settings, creates SQLite tables, and seeds the
catalog metadata.

Testing:

```bash
poetry run pytest
```

Production-like local run:

```bash
NODE_ENV=production poetry run uvicorn src.main:app --host 0.0.0.0 --port ${PORT:-8000}
```

Production mode does not create tables or seed the database. Ensure the SQLite
database, model catalog data, and `.pkl` artifacts are already available before
starting the server.

## API Overview

Base path: `/api/v1`

| Method | Path | Auth | Purpose |
| --- | --- | --- | --- |
| `GET` | `/health` | No | Health check. |
| `POST` | `/api/v1/auth/register` | No | Create user and set auth cookie. |
| `POST` | `/api/v1/auth/login` | No | Authenticate user and set auth cookie. |
| `POST` | `/api/v1/auth/logout` | Cookie | Delete auth cookie. |
| `GET` | `/api/v1/auth/me` | Cookie | Return current user. |
| `GET` | `/api/v1/models` | No | List available models. |
| `GET` | `/api/v1/models/{model_id}/schema` | No | Return model metadata, variables, and R-squared. |
| `GET` | `/api/v1/models/{model_id}/variables` | No | Return input variable metadata for a model. |
| `POST` | `/api/v1/models/{model_id}/predict` | Cookie | Generic prediction endpoint with rate limiting. |
| `POST` | `/api/v1/predictions/economic-growth` | Cookie | Legacy typed endpoint for economic growth. |
| `POST` | `/api/v1/predictions/unemployment` | Cookie | Legacy typed endpoint for unemployment. |
| `POST` | `/api/v1/predictions/business-growth` | Cookie | Legacy typed endpoint for business growth. |

Generic prediction request example:

```json
{
  "values": {
    "delta_ln_EXP": 0.05,
    "delta_ln_IMP": 0.03
  }
}
```

The response includes the predicted target value, R-squared, values used after
fallback resolution, contribution per variable, artifact version, and training
date.

## Authentication And Rate Limits

- Passwords are hashed with bcrypt before persistence.
- JWTs are stored in the `access_token` httpOnly cookie.
- `get_current_user` rejects missing, invalid, expired, or orphaned tokens.
- The generic prediction endpoint is limited to 20 requests per authenticated user every 5 minutes.
- The limiter is in-memory and process-local, so it resets on restart and is not shared across workers.
